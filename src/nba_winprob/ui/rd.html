Logistic regression on a diffusion basis

A scoring margin behaves like a random walk, so win probability tracks the lead divided by the time still left to overturn it. Feeding the model those ratios directly beat the previous 400-tree XGBoost, which was fitting noise. Post-hoc calibration was tested again and rejected: the model is already calibrated.

For non-technical users

We chose this model because it gave the most reliable win chances on games it had never seen before. The previous model was a large decision-tree ensemble that had learned too much detail from past games; a simpler model, given a better way to describe the score and the clock, predicted future games more accurately. We tested several ways to adjust its percentages afterwards, but they made the results less reliable, so the percentages are used as the model produces them. The AI analyst is separate: it can explain what may be affecting a game using verified information, but it does not change the model’s percentage.

Baseline: XGBoost game state model 14 features

The first benchmark was a raw XGBoost model trained on score, clock, score differential, recent scoring runs, overtime state, and season-level team context.

  • Outcome: a usable live probability engine.
  • Limitation: generic home-court assumptions could miss team-specific venue performance.
Baseline method: 14-feature XGBoost · 0.1687 Brier
02

Calibration experiments isotonic

Isotonic regression was tested to lift or lower probability ranges where historical outcomes suggested the raw model was miscalibrated.

  • Global row-level calibration over-weighted repeated plays from the same game.
  • Q4-only calibration created a distribution mismatch when applied to all quarters.
Result: no reliable improvement over raw probabilities.
03

Game-level calibration one game / one outcome

Each game was reduced to one average prediction and one final outcome so correlated play rows would not look like independent examples.

  • This fixed the independence problem during fitting.
  • But game-average probabilities occupy a narrow range and were later applied to wide per-play probabilities.
Result: Brier worsened to 0.1897; rejected.
04

Team context upgrade superseded

The model gained team-specific context rather than treating home court as one universal effect.

  • Home and road win percentages.
  • Home and road average margins.
  • Opponent-adjusted Elo ratings.
Result: raw test Brier 0.1644; ROC-AUC 0.8332.
05

Temperature scaling after isotonic not shipped

A one-parameter temperature adjustment was tested on the isotonic-calibrated setup. It preserved ranking better than a free-form remap, but did not beat the raw 20-feature model.

Result: 0.1645 Brier vs raw 0.1644; raw stayed in production at the time.
06

Diffusion basis, linear model current model

Rolling chronological folds showed the 400-tree XGBoost was overfitting: early stopping alone chose roughly 90 trees and recovered most of the gap. Handing a regularized logistic model the ratios that describe a scoring random walk beat both.

  • Lead divided by the square root of time remaining, and by time remaining.
  • Pre-game win/loss records dropped: adding them back to the corrected data changes nothing measurable, confirming Elo already carries that signal.
  • A pre-game rating edge decayed toward zero as the clock runs out.
Result: Brier 0.1511 vs 0.1656; ROC-AUC 0.861. Measured across five seasons after a feature-table rebuild corrected pre-game context that had been left at placeholder values for a quarter of games.

How the AI analyst works

A second opinion, not a replacement model

What Gemini receives

The analyst receives the model probability plus the current game state and supporting context. For live analysis that includes the score, clock, recent scoring run, team records, venue splits, Elo, player box-score data, fouls, and recent plays.

For pregame or historical analysis, official injury and transaction context is limited to information published before the game state.

What it returns

Gemini must return structured output: an analyst probability for the home team, confidence, direction versus the model, a short headline, key factors, and reasoning. The UI displays the model and analyst probabilities separately so disagreement is visible.

The analyst does not retrain the win-probability model and does not secretly change its probability.

Technical detail

Why repeated play rows need care

A single game creates many play-level predictions but only one final outcome. Treating every row as independent can make one game count hundreds of times during calibration. The benchmark therefore keeps the untouched game split and evaluates probabilities against the final game result without pretending those rows are independent games. The baseline comparison is the old raw 14-feature XGBoost model; the temperature check is the temperature-scaled version of the isotonic calibration path.

What “home/road splits” actually means

The feature set uses each team’s own venue history: home and road win percentage plus home and road average margin. It does not use another team’s home record as a proxy. Elo adds opponent-adjusted strength so the model can distinguish schedule quality from a simple win total.

How to read the Brier score

Brier score measures the distance between a predicted probability and the eventual result. A confident correct prediction scores well; a confident wrong prediction is penalized heavily. That is why the lowest value on the same untouched test set determines the production choice.

Grounding and limits

Gemini is instructed to use only facts supplied in the prompt. It must not invent injuries, trades, signings, depth, coaching tendencies, or historical claims. If official context is unavailable, it must say so. Identical requests are cached and duplicate in-flight requests are combined to reduce Gemini quota usage.

Why raw is the final choice

Calibration is not automatically better. On the active untouched test set, raw XGBoost produced the lowest Brier score. The analyst receives verified official injury and transaction context separately; those facts are not silently injected into the trained model until they beat this benchmark.
